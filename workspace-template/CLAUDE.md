# 工作区规则（多账号接力模板）

> 用法：把整个 `workspace-template/` 里的东西复制到你的工作文件夹根目录（比如 `D:\work`），在 Claude 桌面版的 Code 里用这个文件夹开对话。按需改下面的内容。

我有多个 Claude 账号在这台电脑上轮流用，额度用完就换号接着干（换号器自动换）。**所有账号的对话记录都存在本机** `~/.claude/projects/<本文件夹编码>*/*.jsonl`，可以直接读，这是最新、最全的进度来源。

## 收到“继续”时（换号器换号后会自动在“总控”里发“继续”）

1. 跑 `python -I _tools/sessions_status.py 48`，读 `_tools/sessions_status.txt`：最近的对话，每个都标了状态（中断 / 等用户 / 完成），还有第一句、用户最后说的、Claude 最后说的。
2. 要接着做的：**中断**的（额度用完、跑到一半、调了工具没结果）、**卡到一半**的、**等用户回复**的（把问题重新摆给用户）。想看细节就直接读那个对话的 jsonl。
3. 不要问“要做什么”，直接开干，在当前对话里汇总。记录几分钟内还在更新的对话说明正在跑，不要重复开。
4. **侧栏结构：一个“总控” + 每个项目一个对话**
   - 每个账号只留一个顶层对话，标题“总控”。收到“继续”的顶层对话（不是别的对话开的），如果本账号还没有未归档的“总控”，先用 `set_session_title` 把自己改名为“总控”。总控绝不归档（它下面的项目对话会被一起归档）。
   - 项目对话都由总控用 `start_session` 开，这样会挂在总控下面。标题只写项目名，不写具体任务，方便下次复用。
   - **能复用就不新开**：先用 `list_sessions` 看本账号总控下面有没有这个项目的对话。有就用 `SendMessage` 发“继续”给它，没有才新开。别的账号开的对话发不了消息，所以每个项目在每个账号里各一个对话，但同一账号里不重复。
   - **顺手清理侧栏**：同一项目的旧对话、已完成/已暂停项目的对话、旧的总控，用 `archive_session` 归档（能恢复，不删除）。正在跑的不动。归档旧总控前先看要留的对话的 `startedBy` 是不是它，是就先别归档；被连带归档了马上 `unarchive_session` 恢复。
5. **必须接最新进度，不能接老进度**
   - 每次“继续”，总控下面的每个项目对话都要检查：别的账号里这个项目有没有比它更新的记录（看 sessions_status 和 jsonl 修改时间）。有更新的，就发“继续”，并附上这个项目所有更新的 jsonl 路径，写清“最新做到哪、用户最后说了什么”。
   - 项目对话收到“继续”，或隔了一段时间重新开始时，**动手前先**跑 `sessions_status.py`，读同一项目里比自己更新的对话末尾（其他账号的都要读），再看 `git log` 和交接文件，以最新的为准。自己记忆里的旧计划跟更新的记录冲突时，作废。
6. **每次换号都复盘**：换号器每切一次号，就在 `~/.claude-instances/_switch_history.jsonl` 里记一条（从哪个号到哪个号、手动/自动、每步几秒、预计/实际用量、“继续”发没发成，`flags` 是它自己标的问题）。总控收到“继续”时，读上次复盘之后的新记录（上次复盘时间记在 `~/.claude-instances/_switch_review.txt`），对照 `_auto_switch.log`、`_auto_continue.log`，看有没有：某一步特别慢、挑号挑错（预计跟实际差很多）、“继续”没发成、被登出、来回切。有问题就记下来（或交给维护换号器的对话去改），没问题只更新复盘时间。汇报一句就行。

## 一个项目一个对话

这里有几个互不相关的项目（见下面的索引）。每个对话只做一个项目，不要把别的项目的事混进来。

## 交接文件（辅助）

- 进度以对话记录为准，不用边做边记。`handoff/<项目>.md` 只记对话记录里不好找的东西：关键路径、链接、用户定下来的决定。到了里程碑顺手更新，`HANDOFF.md` 索引那一行同步。
- 只想查用户说过什么：`python -I _tools/recent_requests.py 24 "<关键词|关键词>"`，结果在 `_tools/recent_requests.txt`。
